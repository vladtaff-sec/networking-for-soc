TCP vs UDP

НадійністьГарантія доставки, ретрансмісіяБез гарантій, втрати ігноруються
ПорядокЗберігається (sequence numbers)Не гарантується
ШвидкістьПовільніше, більше службових данихШвидко, мінімум накладних
Заголовок20+ байт8 байт
ДеHTTP, HTTPS, SSH, SMB, RDP, поштаDNS, DHCP, NTP, SNMP, VoIP, стріми

Чому DNS-запит іде по UDP, а zone transfer по TCP?

Звичайний запит крихітний — влазить в одну датаграму, і три пакети handshake заради 50 байт були б марнотратством. Zone transfer (AXFR) — це передача всієї бази записів зони: великий обсяг, де втрата шматка неприпустима, тому TCP.

Чому це важливо для SOC

UDP не має стану — тому його легко спуфити і використовувати для ампліфікації в DDoS (DNS, NTP, memcached). А відсутність handshake ускладнює атрибуцію джерела.

Фундамент · 04 · ФОКУС

Three-way handshake і прапорці TCP

КРОК 1

SYN →

Клієнт: «хочу з'єднатись», надсилає свій sequence number.

КРОК 2

← SYN/ACK

Сервер: «згоден, і я теж хочу» — підтверджує й шле свій SEQ.

КРОК 3

ACK →

Клієнт підтверджує. З'єднання встановлено, летять дані.

Найчастіша помилка — переставити місцями кроки 2 і 3. Запам'ятай як діалог: питання → відповідь із зустрічним питанням → підтвердження. Розрив з'єднання окремо: FIN → ACK → FIN → ACK.

Фундамент · 05 · ФОКУС

Три відповіді на SYN: open, closed, filtered

Це різниця, яку питають на кожній співбесіді — і саме вона відрізняє closed від filtered у Nmap.

OPEN

Відповідь: SYN/ACK

Сервіс живий і слухає порт. Nmap завершить або скине з'єднання і позначить порт відкритим.

CLOSED

Відповідь: RST/ACK

Хост живий, але на цьому порту ніхто не слухає. Це активна відмова — машина існує, і це вже інформація для атакуючого.

FILTERED

Відповіді немає взагалі

Фаєрвол мовчки дропнув пакет. Клієнт робить ретрансмісії і зрештою здається по таймауту. Іноді натомість приходить ICMP unreachable.

Практичний висновок для SOC: RST/ACK у відповідь ≠ «нас захистили». Це означає, що хост відповідає — а отже, видимий для розвідки. Мовчазний дроп (DROP замість REJECT) розкриває атакуючому менше.
У логах фаєрвола шукай патерн: один src_ip → багато dst_port за короткий час = сканування портів; один dst_port → багато dst_ip = пошук конкретного вразливого сервісу по мережі (напр. 445).

Чому це критично для аналітика

Дивлячись на алерт, ти миттєво маєш розуміти напрямок трафіку: приватна → публічна це вихід назовні (можливий C2 або ексфільтрація), публічна → приватна це вхід ззовні (можлива атака на периметр), приватна → приватна це внутрішній рух (можливий lateral movement).

Бонус: інші зарезервовані

  • 127.0.0.0/8 — loopback, сам хост
  • 169.254.0.0/16 — APIPA, DHCP не спрацював
  • 100.64.0.0/10 — CGNAT провайдерів

Адресація · 08 · ФОКУС

TTL — лічильник хопів, а не секунд

Як працює

У кожному IP-пакеті є поле TTL (Time To Live). Кожен роутер на шляху зменшує його на одиницю. Коли TTL досягає нуля — пакет відкидається, а відправнику летить ICMP Time Exceeded.

Це захист від вічних петель маршрутизації: без TTL зациклений пакет ходив би по мережі назавжди.

Поширена помилка — вважати TTL «часом життя сесії» в секундах. Ні: це кількість переходів між роутерами.

Traceroute побудований саме на цьому

# шле пакети з наростаючим TTL
TTL=1 → помирає на 1-му роутері → той відповідає
TTL=2 → помирає на 2-му → відповідає
TTL=3 → ... і так до цілі

Так збирається список усіх вузлів на маршруті.

Форензичний бонус

Початковий TTL натякає на ОС відправника: 64 — Linux/macOS, 128 — Windows, 255 — мережеве обладнання. Бачиш TTL 117 — імовірно Windows за 11 хопів від тебе.

Протоколи · 10

ARP — міст між IP і MAC

Що робить

Щоб надіслати кадр у локальній мережі, хосту потрібна MAC-адреса отримувача, а він знає лише IP. ARP закриває цю прогалину: працює на L2, тільки в межах локального сегмента.

// широкомовний запит на всю мережу
ARP Request:  «Хто має 192.168.1.10?
              відповідайте на aa:bb:cc:dd:ee:ff»
ARP Reply:    «Це я, мій MAC 11:22:33:44:55:66»

Результат кешується: arp -a покаже таблицю.

ARP spoofing / poisoning

У протоколі немає автентифікації — приймається будь-яка відповідь. Атакуючий шле фальшиві ARP Reply: «шлюз 192.168.1.1 — це мій MAC». Трафік жертви починає йти через нього.

Це класичний Man-in-the-Middle у локальній мережі: перехоплення сесій, підміна даних, збір креденшелів.

Як виявляти

  • Один MAC відповідає за кілька різних IP
  • Раптова зміна MAC для IP шлюзу
  • Аномально багато ARP-трафіку (gratuitous ARP)
  • У Wireshark: arp.duplicate-address-detected
Протоколи · 11

DHCP — автоматична видача адрес

Процес DORA

D

Discover

Клієнт кричить у broadcast: «є тут DHCP-сервер?»

O

Offer

Сервер пропонує вільну IP-адресу і параметри.

R

Request

Клієнт офіційно просить саме цю адресу.

A

Acknowledge

Сервер підтверджує і фіксує оренду (lease).

Що видає сервер

  • IP-адресу і маску підмережі
  • Шлюз за замовчуванням
  • DNS-сервери — ось де ризик
  • Термін оренди (lease time)

Порти: сервер 67/UDP, клієнт 68/UDP.

Rogue DHCP — атака

Атакуючий піднімає свій DHCP-сервер і відповідає швидше за легітимний. Видає жертвам свій IP як шлюз і DNS — і весь трафік мережі йде через нього. Знову MitM, але масштабніший за ARP spoofing.

Захист: DHCP snooping на свічах — дозволяє DHCP-відповіді лише з довірених портів.

Для розслідування DHCP-логи безцінні: вони зв'язують IP-адресу з MAC і часом. Без них ти не доведеш, який саме пристрій мав цю IP о 10:04.
Протоколи · 12

NAT — трансляція адрес

Навіщо

Публічних IPv4-адрес не вистачає. NAT дозволяє сотням внутрішніх приватних адрес виходити в інтернет через одну публічну. Роутер підміняє адресу джерела і запам'ятовує відповідність у таблиці трансляцій.

192.168.1.15:52134  →  NAT  →  203.0.113.7:61001
192.168.1.22:49877  →  NAT  →  203.0.113.7:61002

Види

  • Static NAT — одна приватна до однієї публічної
  • Dynamic NAT — з пулу адрес
  • PAT / NAT overload — багато до однієї через різні порти. Це те, що працює вдома й в офісі

Проблема для розслідування

Ззовні всі співробітники виглядають як одна IP-адреса. Щоб з'ясувати, хто саме звертався до шкідливого домену, потрібні NAT-логи з таймстемпами і портами — інакше слід обривається на периметрі.

Побічний ефект: NAT працює як примітивний фаєрвол — ззовні не можна ініціювати з'єднання до внутрішнього хоста, бо в таблиці трансляцій немає відповідного запису. Але це не заміна фаєрволу.

Протоколи · 14

DNS в атаках — найнедооцінене джерело

ТУНЕЛЮВАННЯ

DNS tunneling

Дані ховають у піддоменах: ZXhmaWx0cmF0ZWQ.evil.com. DNS майже ніколи не блокують, тому це надійний канал ексфільтрації та C2.

Ознаки: аномально довгі імена, багато унікальних піддоменів одного домену, високий обсяг TXT-запитів, запити без подальших з'єднань.

DGA

Domain Generation Algorithm

Малваре щодня генерує сотні псевдовипадкових доменів (kqxwmz3f9a.net) і пробує їх по черзі, доки не знайде живий C2. Блокувати по списку марно.

Ознаки: сплеск NXDOMAIN-відповідей з одного хоста, домени з високою ентропією імені.

FAST FLUX

Швидка зміна IP

Один домен постійно міняє A-записи з дуже низьким TTL, ховаючи реальну інфраструктуру за ботнетом проксі.

Ознаки: TTL у кілька секунд, десятки різних IP з різних країн за короткий час.

ІНШЕ

Отруєння і підміна

  • Cache poisoning — підсунути фальшиву відповідь у кеш резолвера
  • Typosquatting — gooogle.com, privatbnk.ua
  • Newly registered domains — домен, зареєстрований учора, у фішингу майже завжди
Правило SOC: DNS-логи — перше, куди дивишся, коли треба зрозуміти, з ким спілкувався заражений хост. Вони фіксують намір навіть тоді, коли саме з'єднання не відбулося.

Що відбувається, коли ти вводиш URL

Питання-фільтр номер один на джуніорських співбесідах. Скелет: кеш → DNS → TCP → TLS → HTTP → рендер.

КРОК 1

Перевірка кешу

Браузер дивиться свій кеш, потім кеш ОС, файл hosts, далі кеш резолвера. Якщо адреса є — DNS пропускається.

КРОК 2

DNS-резолв

Запит по UDP/53 до резолвера, рекурсивно до авторитетного сервера. Отримуємо IP.

КРОК 3

TCP-з'єднання

Three-way handshake на порт 443: SYN → SYN/ACK → ACK.

КРОК 4

TLS handshake

Узгодження версії й шифрів, сервер надсилає сертифікат, браузер його перевіряє, узгоджується сеансовий ключ.

КРОК 5

HTTP-запит

GET / HTTP/1.1 з заголовками. Сервер відповідає статусом і HTML-кодом.

КРОК 6

Рендеринг

Браузер парсить HTML, довантажує CSS, JS, зображення окремими запитами, будує DOM і малює сторінку.

Сильна відповідь згадує усі протоколи поіменно: DNS (UDP/53), TCP (443), TLS, HTTP. Якщо в URL стоїть https — крок з TLS обов'язковий, його пропуск одразу помітний інтерв'юеру.
Веб · 16 · ФОКУС

TLS: чому браузер вірить сертифікату

Ланцюжок довіри

Root CA            // вшитий у браузер/ОС
   └─ підписує
Intermediate CA
   └─ підписує
Сертифікат google.com  // leaf

У браузері з коробки є список довірених кореневих CA з їхніми публічними ключами. Браузер перевіряє підпис сертифіката ключем CA і йде вгору по ланцюжку до відомого кореня.

Аналогія: ти довіряєш паспорту незнайомця не тому, що знаєш його, а тому, що документ видала держава, якій ти довіряєш, і має захисні елементи, які ти вмієш перевірити.

Що саме перевіряється

  • Підпис — і ланцюжок веде до довіреного кореня
  • Домен у полі SAN збігається з тим, куди ти йдеш
  • Термін дії не минув і вже почався
  • Не відкликаний — перевірка через CRL/OCSP

Гібридне шифрування

Асиметрика (повільна, але безпечна) використовується лише щоб узгодити сеансовий ключ. Далі весь трафік іде симетричним шифром (швидким). Найкраще з обох світів.

Для SOC

Self-signed сертифікат на внутрішньому сервері — рутина. Self-signed на зовнішньому з'єднанні або сертифікат, виданий учора для домену-одноденки — привід копати. Малваре часто ховає C2 за TLS: дивись на JA3-відбиток і аномальні cipher suites.

Інструменти · 17

Мережеві пристрої та засоби захисту

L2

Switch

Комутує кадри всередині сегмента за MAC-адресами. Тримає MAC-таблицю. Підтримує VLAN — логічне розділення мережі.

L3

Router

Маршрутизує пакети між мережами за IP-адресами, спираючись на таблицю маршрутизації. Зменшує TTL на кожному переході.

L3–L7

Firewall

Фільтрує трафік за правилами. Stateful відстежує стан з'єднань. NGFW бачить застосунки й вміє DPI.

L7

Proxy

Посередник для вебтрафіку: фільтрує URL, кешує, логує кожен запит. Найцінніше джерело для розслідування «хто клікнув на фішинг».

ПАСИВНО

IDS

Стоїть поза потоком (на span-порту), аналізує копію трафіку і лише сигналізує. Не блокує, тому не ламає легітимний трафік.

В РОЗРИВ

IPS

Стоїть у розриві (inline), трафік іде крізь нього — тому може заблокувати атаку. Ціна: false positive ріже робочий трафік.

Різницю IDS vs IPS питають майже завжди. Формула відповіді: «IDS — камера спостереження, бачить і кричить; IPS — охоронець у дверях, бачить і не пускає. Ціна IPS — ризик заблокувати своїх». Snort і Suricata вміють працювати в обох режимах.

Wireshark — фільтри, які рятують час

Display-фільтри (базові)

# за адресою і портом
ip.addr == 10.0.0.5
ip.src == 10.0.0.5 && ip.dst == 8.8.8.8
tcp.port == 445
udp.port == 53

# за протоколом
http || dns || smb2
tls.handshake.type == 1   # ClientHello

Полювання

# лише SYN без ACK = сканування портів
tcp.flags.syn==1 && tcp.flags.ack==0

# скиди з'єднань
tcp.flags.reset == 1

# POST-запити — часто ексфільтрація
http.request.method == "POST"

# підозрілий домен у DNS
dns.qry.name contains "evil"

# паролі у відкритому тексті
frame contains "password"

Робочий процес аналітика

  • Statistics → Conversations — хто з ким і скільки говорив. Найбільші сесії — перші підозрювані
  • Statistics → Protocol Hierarchy — що взагалі є в дампі, які протоколи аномально представлені
  • Follow → TCP Stream — прочитати діалог цілком, як текст
  • File → Export Objects → HTTP — витягти передані файли з трафіку
  • Statistics → IO Graph — побачити регулярність (beaconing видно очима)
Порада для іспиту: не намагайся читати дамп підряд. Спершу Conversations і Protocol Hierarchy, щоб звузити коло, і тільки потім занурюйся в конкретні пакети.
Інструменти · 19

tcpdump і Nmap

tcpdump — коли немає GUI

# писати дамп у файл (потім відкриєш у Wireshark)
tcpdump -i eth0 -nn -w capture.pcap

# -nn = не резолвити імена й порти
tcpdump -nn host 10.0.0.5
tcpdump -nn port 445
tcpdump -nn src 10.0.0.5 and dst port 443

# лише SYN-пакети (пошук сканування)
tcpdump -nn 'tcp[tcpflags] & tcp-syn != 0'

# читати збережений файл
tcpdump -nn -r capture.pcap
На бойовому сервері завжди пиши -w file.pcap: спершу зібрав, потім аналізуй окремо. Аналіз наживо втрачає пакети.

Nmap — розвідка (і те, що ти бачиш у логах)

# швидкий SYN-скан топ-портів
nmap -sS 10.0.0.0/24

# версії сервісів + ОС
nmap -sV -O 10.0.0.5

# усі 65535 портів
nmap -p- 10.0.0.5

# скрипти виявлення вразливостей
nmap --script vuln 10.0.0.5

Погляд синьої команди

Тобі не треба сканувати — тобі треба впізнавати скан у логах. Ознаки: один src_ip звертається до десятків портів одного хоста за секунди, або до одного порту багатьох хостів. У фаєрволі це стіна записів deny з однієї адреси.

Мережеві джерела логів для SIEM

Фаєрвол / VPN

Хто заходить ззовні, які з'єднання дозволено й заблоковано. Периметр — перше, що підключають.

Дає src/dst IP, порти, action, обсяг

Проксі

Кожен вебзапит користувача з URL, User-Agent, обсягом і вердиктом категорії.

Дає відповідь «хто клікнув на фішинг»

DNS

Кожен резолв домену з хоста. Фіксує намір навіть без успішного з'єднання.

Дає C2, тунелі, DGA, typosquatting

NetFlow / IPFIX

Метадані з'єднань без вмісту: хто, з ким, скільки, як довго. Дешево зберігати.

Дає beaconing, ексфільтрацію, lateral

IDS / IPS

Спрацювання сигнатур Snort/Suricata на відомі експлойти й патерни малваре.

Дає готові алерти з контекстом

DHCP

Зв'язка IP ↔ MAC ↔ час. Без неї IP-адреса в логах не вказує на конкретний пристрій.

Дає атрибуцію пристрою

Питання зі співбесіди «які 5 джерел підключиш першими до SIEM з обмеженим бюджетом»: контролер домену (автентифікація), поштовий шлюз (вектор №1), EDR (де атака приземляється), фаєрвол/VPN (периметр), проксі/DNS (кліки і C2). Логіка відповіді: покрити весь ланцюжок атаки, а не один її рівень.
Шпаргалка · 22

Мінімум, який має бути в голові

Числа

  • Приватні: 10/8 · 172.16–31 · 192.168/16
  • /24 = 256 адрес, 254 хости (мінус мережа й broadcast)
  • Хости = 2(32−префікс) − 2
  • TTL: 64 Linux · 128 Windows · 255 мережеве
  • Порти: 22 · 25 · 53 · 80 · 443 · 445 · 3389 · 389 · 88

Послідовності

  • Handshake: SYN → SYN/ACK → ACK
  • Розрив: FIN → ACK → FIN → ACK
  • DHCP: Discover → Offer → Request → Ack
  • URL: кеш → DNS → TCP → TLS → HTTP → рендер
  • DNS: кеш → root → TLD → авторитетний

Розрізняти без вагань

  • RST/ACK = closed (хост живий) · тиша = filtered
  • IDS пасивно сигналізує · IPS inline блокує
  • TCP надійність · UDP швидкість
  • ARP IP→MAC (L2) · DNS ім'я→IP (L7)
  • Хешування незворотне · шифрування зворотне

Формулювання для співбесіди

  • Завжди називай протокол і порт, не просто «запит»
  • Прив'язуй до MITRE ATT&CK, якщо доречно
  • Відповідь = що бачу → що це означає → що роблю
  • Не обривай на першому кроці — розгортай ланцюжок
